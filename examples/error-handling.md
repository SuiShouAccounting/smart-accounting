# 网关调用失败与错误处理样例

## 何时参考这个文件

当网关调用失败、返回错误 code、或环境不可用时参考。

## 失败处理原则

本技能所有操作都通过统一网关完成，失败处理基于返回的 `code` 分类，**绝不盲目原地重试**：

```
网关请求
   ├─ code==0  → 成功，取 data 输出结果
   ├─ 脚本本地报「授权信息缺失」 → 凭证还没写入，引导用户提供（不要说"过期"）
   ├─ 授权失效（1100） → 先确认凭证确已写入 config，再引导重新提供，不重试
   ├─ 参数格式错误（1200） → 按 msg 修正取值后重试一次；msg 表明该能力本账本不支持则改走支持口径
   ├─ 接口不支持（1300） → 业务语言告知"当前不支持"，不重试
   ├─ 缺少必填参数（1400） → 补齐参数后重试一次
   ├─ 限流（1500） → 稍等片刻后重试一次
   ├─ 上游处理失败（2100/2200） → 查询类可稍后重试一次；记账类严禁重试
   ├─ 网络/连接失败（请求异常、超时） → 有缓存用缓存，否则业务话术告知（记账类超时同样严禁自动重试）
   └─ 其它 code → 按 msg 用业务话术说明，停止重试
```

**硬约束**：
1. **绝不循环重试同一请求**：不因用户催促就无脑重试
2. **降级过程对用户透明**：用户只看到最终结果或业务话术错误
3. **配置缺失不走重试**：走引导流程（让用户提供凭证/选账本）
4. **缓存兜底**：网关失败时，只要 `config/` 缓存有数据就优先用缓存回答

## 场景 1：授权失效（不重试，引导）

### 样例 1.1：凭证过期

（模型内部、不对用户展示：网关返回 code=1100 授权失效）

```
用户：记一笔午餐20块

模型：授权信息好像过期啦，麻烦到随手记/神象云 App 的"我的"页面拿一份最新的发给我，咱们接着记～
```

✅ **关键点**：授权失效不降级、不重试，直接引导。

❌ **反例**：反复重试或暴露技术细节

```
模型（错误）：调用返回 1100，再试一次...（实际会一直失败）
```

**为什么错**：授权失效不是临时错误，重试无意义；应直接引导用户更新凭证。

## 场景 2：参数/接口错误（检查后重试一次）

### 样例 2.1：缺少业务参数

（模型内部、不对用户展示：网关返回 code=1400 缺少必填参数，如账户或分类）

```
用户：记一笔午餐

模型：还差一点点信息～这笔"午餐"，您想记到哪个分类呢？比如"伙食费、早餐、中餐"这些都可以～
```

✅ **关键点**：code 1400 往往代表缺少账户/分类等必填业务参数，需向用户补齐一个输入；补齐后正常再走一次。

## 场景 3：网络错误 → 缓存兜底

### 样例 3.1：网络断了，用缓存

（模型内部、不对用户展示：网关请求失败（网络/超时）；检查 config/sui_base_tag.json 有缓存数据，改用缓存回答）

```
用户：查询账户

模型：您的账户如下（当前账本：家庭账本1）：

| 父级账户 | 子账户 |
| ---- | ---------------- |
| 现金账户 | 现金、账户A、账户AA、账户AB |
| ... | （略） |

> 网络好像有点卡，先给您看的是上次的记录，联网后我会自动帮您刷新～
```

✅ **关键点**：
1. **优先用缓存**回答，不直接报错
2. **一句话提示**数据可能过期，不暴露"超时""请求失败"等技术词

❌ **反例**：直接报错给用户

```
模型（错误）：查询失败：网络超时（请求异常），请稍后重试。
```

**为什么错**：能兜底却不兜底，用户体验差。

## 场景 4：无数据 / 功能不可用

### 样例 4.1：查询结果为空

（模型内部、不对用户展示：网关成功，但 data 为空数组）

```
用户：查询项目

模型：这个账本里暂时还没有项目数据～
```

✅ **关键点**：不要暴露"空数组""data=[]"，用业务语言"暂无数据"。

### 样例 4.2：不支持的功能

（模型内部、不对用户展示：网关无修改已有记账记录的能力）

```
用户：把上个月的那笔改掉

模型：这个功能我暂时还做不到呢，真是不好意思～不过记账、查账这些我都可以帮您～
```

✅ **关键点**：能力边界诚实告知，不硬查、不绕路、不编造。

## 错误处理速查表

| 网关 code / 情况 | 处理 | 用户看到什么 |
|---|---|---|
| `code==0` | 取 data 输出 | 业务结果 |
| 脚本本地报「授权信息缺失」 | 引导提供凭证（首次配置场景，**不说"过期"**） | "麻烦把授权信息发我一份～" |
| `code==1100` 授权失效 | 先确认凭证已写入 config；不重试，引导重新提供 | "授权好像过期啦，麻烦发我新的～" |
| `code==1200` 参数格式错 | 按 msg 修正后重试一次；msg 表明本账本不支持该能力则改走支持口径 | 用户无感知（静默修正）/ 业务语言说明 |
| `code==1300` 接口不支持 | 不重试 | "当前还不支持这个操作～" |
| `code==1400` 缺少必填参数 | 补齐后重试一次 | 让用户补一个必要输入（温和地问） |
| `code==1500` 限流 | 稍后重试一次 | "操作有点频繁，稍等一会儿～" |
| `code==2100/2200` 上游处理失败 | 查询类稍后重试一次；**记账类严禁重试** | "数据这会儿有点问题，稍后再试～" |
| 网络失败 / 超时 | 用缓存兜底（记账类超时严禁自动重试） | 缓存数据 + "网络卡了一下"提示 |
| 有缓存 | 优先用缓存 | 缓存数据 |
| 无缓存且网络失败 | 不硬查 | "网络好像有点卡，我过会儿再帮您试一次" |
| 数据为空 | 直接说无数据 | "暂时还没有相关数据～" |
| 能力不支持 | 不编造 | "这个我暂时还不会，不过其它的可以帮您～" |

## 关键原则

1. **能兜底就兜底，不报错给用户**
2. **处理过程静默，用户只看最终结果**
3. **配置/凭证类问题必须引导用户补全**，不能靠重试解决
4. **缓存永远是最后兜底**，即使网关全挂，缓存有数据就先用
5. **业务话术替代技术错误**："网络超时" → "网络不太好"；"授权失效" → "请更新访问凭证"
