# 查询基础资料样例

## 何时参考这个文件

当用户说"查询账户/分类/成员/商家/项目"、"查基础资料"时参考。

## 核心原则

- **缓存优先**：先读 `config/sui_base_tag.json`，有数据直接用
- **静默刷新**：缓存为空时调统一网关拉取（`list_book_accounts`/`list_book_categories` 等），不告诉用户"正在查询"
- **分组展示**：账户按类型分组、分类按一级/二级层级展示

## 场景 1：查询账户（分组）

### 样例 1.1：完整账户查询

```
用户：查询下我的账户

模型：您的账户如下（当前账本：家庭账本1）：

| 父级账户 | 子账户 |
| ---- | ---------------- |
| 现金账户 | 现金、账户A、账户AA、账户AB |
| 储蓄账户 | 银行卡 |
| 虚拟账户 | 支付宝、微信钱包 |
| 投资账户 | 基金账户、余额宝、股票账户 |
| 债权账户 | 应收款项、应收A、应收AA、借出款、借出款1 |
| 信用账户 | 信用卡、信用支付A、信用支付B |
| 负债账户 | 应付款项、负债账户A |

记账时从上面这些可记账的账户里选一个就可以啦～
```

✅ **关键点**：
1. 按账户类型分组，父级作列标题，子集用顿号分隔——这是 `references/output-rules.md` 强制的表格格式
2. 展示可记账账户，供记账时选择

❌ **反例 1**：单列展示

```
模型（错误）：
1. 现金
2. 账户A
...
20. 负债账户A
```

**为什么错**：单列展示 20 个账户刷屏，且失去了类型分组信息。

❌ **反例 2**：展示原始 JSON

```
模型（错误）：
[{"id":"<账户ID>","name":"现金","type":"0","act_enable":true,...}]
```

**为什么错**：暴露了 id/act_enable 等技术字段，用户看不懂。

## 场景 2：查询分类（层级）

### 样例 2.1：支出分类查询

```
用户：查询下支出分类

模型：### 支出分类

| 父级分类 | 子分类 |
| ---- | --------------- |
| 食品酒水 | 伙食费、早餐、中餐、晚餐、水果、零食、买菜、柴米油盐 等 |
| 居家生活 | 房租、物业费、电费、水费、燃气费、电视费、维修费、快递费 |
| 交流通讯 | 手机话费、网费、座机费 |
| 休闲娱乐 | 彩票、棋牌、麻将、话剧、KTV、网游、运动、电影 等 |
| 人情费用 | 红包、白事、升学、满月、寿辰、婚嫁、乔迁、孝敬长辈 等 |
| 宝宝费用 | 妈妈用品、医疗护理、宝宝用品、宝宝教育、宝宝食品、宝宝其他 |
| 行车交通 | 地铁、公交、保养、保险、停车、维修、加油、打车 等 |
| 购物消费 | 日常用品、电子数码、美妆护肤、衣裤鞋帽、超市购物、家具家电 等 |

记账时从上面挑个分类就行～（分类多，这里先展示前 8 组，要看其它组直接说组名）
```

✅ **关键点**：
1. **双列表格**（父级分类 | 子分类）——`references/output-rules.md` 强制格式；**纯文本"一级：二级、二级"整段串是反例**
2. 子分类太多时每组最多展示 8 个、以"等"收口，不整段输出
3. 最多展示前 8 组，末尾给引导语（说组名可继续看）

❌ **反例**：树形缩进，或"一级分类：二级、二级"纯文本整段串

```
模型（错误）：
食品酒水：伙食费、早餐、中餐、晚餐、水果、零食、买菜、柴米油盐、饮料酒水、外出美食
居家生活：房租、物业费、电费、水费、燃气费、电视费、维修费、快递费
...
```

**为什么错**：没有表格结构、整段刷屏，违反 output-rules.md 分类列表强制规范。

## 场景 3：查询成员/商家/项目

### 样例 3.1：查询成员

```
用户：查询下账本成员

模型：账本"我的家庭账本"的成员（共 9 位）：

| 序号 | 成员 | 序号 | 成员 |
| -- | ----- | -- | ----- |
| 1 | 本人 | 5 | 岳父 |
| 2 | 配偶 | 6 | 岳母 |
| 3 | 父亲 | 7 | 儿子 |
| 4 | 母亲 | 8 | 女儿 |
| 9 | 其他 |  |  |
```

✅ **关键点**：成员/商家/项目这类扁平列表同样**8 个一组走表格**（通用列表规则；账本列表例外：10 个一组 3 列，见 output-rules.md「账本列表」节）；纯文本顿号串是反例。

### 样例 3.2：查询商家

```
用户：查询下商家

模型：账本"我的家庭账本"的商家（共 18 家）：

| 商家 |
| ---- |
| 超市、便利店、网店、外卖、出行、电信运营商、电力公司、自来水公司、燃气公司、物业、加油站、停车场、医院、药店、学校、餐厅、商场、其他 |
```

### 样例 3.3：查询项目

```
用户：有哪些项目？

模型：当前账本的项目列表：

| 序号 | 项目 | 序号 | 项目 |
| -- | ----- | -- | ----- |
| 1 | 孩子教育 | 4 | 购物 |
| 2 | 出差 | 5 | 宝宝 |
| 3 | 汽车 | 6 | 红包 |
```

（模型内部、不对用户展示：SSJ 账本项目为扁平一级；SXY 账本项目可能有父子层级，展示时把顶层与子项目一并列出、可记账的才供选择。返回为空时告知"这个账本里暂时还没有项目数据～"。）

## 场景 4：切换默认账本

### 样例 4.1：切换默认账本

```
用户：切换到"装修账本"

模型：好嘞，默认账本已经帮您切到"装修账本"啦～
```

> 切换账本后，记账时按新账本的可记账账户语义填入（默认"现金"，详见 references/accounting.md）。

## 边界场景

### 缓存为空时的静默刷新

（模型内部、不对用户展示：缓存为空 → 静默调网关刷新，拿到数据后才输出。）

```
用户：查询分类

模型：### 支出分类

| 父级分类 | 子分类 |
| ---- | --------------- |
| （数据，同样例 2.1 表格格式） | ... |
```

✅ **不要告诉用户**"正在查询"、"请稍等"。直接返回结果即可。

### 刷新缓存

（模型内部、不对用户展示：静默调网关刷新，覆盖缓存。）

```
用户：刷新下分类数据

模型：分类数据已经帮您刷新好啦～
```

✅ **一句话总结**，不暴露具体刷新了多少条、经什么途径拉的。
