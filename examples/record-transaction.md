# 记账场景样例

## 何时参考这个文件

当用户说"记账"、"记一笔"、"记流水"、"花/赚/转多少钱"时参考。本技能通过统一网关 `create_transaction` 记账（支持支出/收入/转账/余额变更）。

## 场景 1：时间智能识别（支出）

### 样例 1.1：中午说吃饭 → 自动选中餐

```
用户：中午吃饭花了20块钱
（当前时间：2026-07-20 12:30）

模型：已记：中餐 20.00 元，现金账户
```

**模型内部流程**：

1. 识别"花了" → 记支出
2. 识别"中午"（12:30） → 时间感知分类 = 中餐
3. 识别金额 "20" → from\_amount="20"
4. 没说账户 → 默认用"现金"账户（缓存中有现金类账户时）；语境能语义匹配（微信/支付宝/刷卡等）则直接用，均不问
5. 静默调网关 `create_transaction` → 成功
6. 用业务语言输出

✅ **关键点**：**单笔、确定、能推断的就直记不问**。不要追问"你想记到哪个分类？"。

### 样例 1.2：晚上说吃饭 → 自动选晚餐

```
用户：我晚上吃饭花了15.5
（当前时间：2026-07-20 19:15）

模型：已记：晚餐 15.50 元，现金账户
```

### 样例 1.3：用户明确指定时段，以用户为准

```
用户：今天早上吃饭花了8块
（当前时间：2026-07-20 14:00）  ← 虽然现在是下午，但用户说"早上"

模型：已记：早餐 8.00 元，现金账户
```

✅ **规则**：用户明确说"早上/中午/晚上"，即使与当前时间冲突，也按用户说的。

## 场景 2：分类模糊匹配

### 样例 2.1：能确定就直记（推荐）

```
用户：今天发工资 1000

模型：已记：工资收入 1000.00 元，现金账户
```

**不需要追问**：工资 → 工资收入，一对一明确匹配。

### 样例 2.2：多分类匹配时，用顿号格式追问

```
用户：今天充了100块话费
（"话费"匹配到"手机话费"，但还有可能匹配"网费"）

模型：您说的"话费"，想记到哪个分类呢？

| 分类 |
| ---- |
| 手机话费、网费 |

选一个就行～

（用户回复后直记）
```

❌ **反例 1**：用序号列表

```
模型（错误）：
1. 手机话费
2. 网费
请回复编号。
```

**为什么错**：违反 `references/output-rules.md` 的列表强制规范——候选必须用表格展示，不用编号列表。

❌ **反例 2**：明明能推断却追问

```
用户：今天打出租车花了30
模型（错误）：你说的"出租车"想记到哪个分类？地铁、公交、打车
```

**为什么错**：出租车 → 打车，语义明确，应直接记账。

```

### 样例 3.2：利息收入

用户：收到一笔利息 0.02 元

模型：已记：利息收入 0.02 元，现金账户
```

## 场景 4：流水显示格式

### 样例 4.1：多笔流水汇总（表格）

```
用户：查询最近7天的流水

模型：最近 7 天共 **15 笔**流水（按时间倒序）：

### 收入 3 笔
| 日期 | 备注 | 分类 | 金额 |
|---|---|---|---|
| 3月19日 | 工资 | 工资收入 | +1000.00 |
| 3月18日 | 工资 | 工资收入 | +1000.00 |
| 3月18日 | 理财收益 | 利息收入 | +0.02 |

### 支出 12 笔
| 日期 | 备注 | 分类 | 金额 |
|---|---|---|---|
| 3月19日 | 地铁 | 地铁 | -9.00 |
| 3月19日 | 中餐 | 中餐 | -30.00 |
...

**小计**：收入 2000.02 元，支出 2860.35 元，结余 -860.33 元。
```

✅ **关键点**：用**表格**展示多笔，用"**小计**"做业务总结。不要把原始 JSON 字段（id/parent\_id/act\_enable）暴露给用户。

❌ **反例**：展示原始 JSON

```
模型（错误）：
{"income":"1000.00","transaction_time":"1784613644000","id":"<交易ID>","category":{"id":"<分类ID>","name":"工资收入",...}}
```

## 场景 5：账户选择

### 样例 5.1：用户没指定账户，缓存有"现金"（默认账户，直接记）

```
用户：买地铁票花了9块
（缓存账户：现金、支付宝、微信钱包）

模型：已记：地铁 9.00 元，现金账户
```

✅ **规则**：用户没说账户且缓存中有"现金"（或名称含"现金"）的可记账账户 → **默认用现金，不问**。

❌ **反例**：缓存里有"现金"账户，还问"您是用哪个账户付的钱呀？"（把账户列表整个展示出来让用户选）

**为什么错**：违反样例 5.1 的默认账户规则——用户没说账户、缓存有现金类账户时应自动填"现金"直接记账；只有**无现金类账户且语境无线索**时才按样例 5.3 问用户。

### 样例 5.2：语境可语义匹配账户（直接记）

```
用户：微信付了杯咖啡15块

模型：已记：咖啡 15.00 元，微信钱包
```

✅ **规则**："微信"→微信钱包、"支付宝"→支付宝、"刷卡"→信用卡——语境能对上就直接用，不问。

### 样例 5.3：无默认账户且语义无法确定（才问）

```
用户：花了30块
（缓存账户：银行卡A、银行卡B、支付宝；无现金类账户，语境无线索）

模型：这笔 30 元想从哪个账户支出呀？

| 账户 |
| ---- |
| 银行卡A、银行卡B、支付宝 |

选一个就行～
```

✅ **规则**：仅在"没有现金类默认账户 + 语境匹配不到/多义"时才问，用表格列出候选，一次只问这一项。

### 样例 5.4：用户指定账户

```
用户：信用卡刷了笔3600的聚餐

模型：已记：聚餐 3600.00 元，信用卡账户
```

## 场景 6：备注处理

### 样例 6.1：用用户原话做备注

```
用户：记一笔：晚上吃饭花了15.5

模型：已记：晚餐 15.50 元，现金账户
（备注 = "晚上吃饭"）
```

### 样例 6.2：用户提供明确备注

```
用户：地铁9块，备注：上班通勤

模型：已记：地铁 9.00 元，现金账户
（备注 = "上班通勤"）
```

## 边界场景

### 用户没说金额

```
用户：记一笔午餐

模型：好呀，这笔午餐花了多少钱呢？
```

### 金额格式不规范

（模型内部、不对用户展示：把"二十块五"解析为 20.50。）

```
用户：打车二十块五

模型：已记：打车 20.50 元，现金账户
```

### 用户没说分类、也推断不出来

```
用户：花了30块
（账本分类列表里有"其他支出"）

模型：已记：其他支出 30.00 元，现金账户
```

✅ **规则**：分类推断不出来时，**优先用账本的"其他"类分类**（名称含"其他"的二级分类，如"其他支出"/"其他收入"），不问用户；账本里没有"其他"类分类时才问。

❌ **反例**：用户只说"昨天花了20块"、分类推断不出来 → 模型不问用户、也不看有没有"其他"类分类，自行新建"杂项"分类再记账

**为什么错**：违反"不得自行新建分类"——正确流程是：语义推断 → "其他"类兜底 → 都没有才问用户；新建分类仅限用户明确要求。

### 账户不存在

```
用户：从招行卡转100到建行卡
（缓存中没有"招行卡"或"建行卡"，当前为 SXY 账本）

模型：不好意思，您在账本里没找到"招行卡"或"建行卡"这些账户～现有的储蓄类账户有：银行卡。
想用现有的账户，还是需要先帮您新建一个账户呢？
```

✅ **规则**：两类账本（SXY/SSJ）都可给"帮您新建"选项（新增/改名两线均支持，见 `references/basic-data.md`）；只给真实可执行的选项，不要说"这类账本不支持"。
